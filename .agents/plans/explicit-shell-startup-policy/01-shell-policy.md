# Work package 1: Public shell startup mode

Prerequisite: confirmed application context in [overview](00-overview.md). Goal: expose explicit non-login invocation without transferring host authority to model inputs. No feature flag or migration is required.

## Change surface

Existing `shell/options.go`: add proposed type `StartupMode string`, constants `StartupModeLogin = "login"` and `StartupModeNonLogin = "non-login"`, proposed field `Options.StartupMode`, and proposed method `Options.Validate() error`. Keep these declarations portable; `catalog/types.go` imports shell options even on Windows. Validate accepts only empty, login and non-login, and rejects negative output caps. Do not execute the binary, probe startup files or resolve PATH in validation. Document that shell executables must accept the selected flag convention; do not reject arbitrary executable paths by basename or add a shell allowlist.

Existing `Options.withDefaults` normalizes empty mode to login alongside existing binary/output defaults and the Env copy. Existing `shell/shell.go` functions `resolveOptions`, `New` and `Run` capture the normalized mode into a proposed unexported scalar `Tool.startupMode`. `resolveOptions` still rejects more than one options value; route both omitted and supplied options through shared validation/defaulting. The existing missing-binary error remains a Run-time `exec_failed` result for the leaf constructor. Unknown mode and negative cap are configuration failures at construction.

At the existing `exec.CommandContext` call, use exactly one flag argument (`-lc` or `-c`) followed by the original `args.Cmd` as a single argument. Do not join, quote, split, trim, prepend, or otherwise rewrite command text. Existing whitespace-only validation may inspect a trimmed copy. No shell wrapper, new interpolation layer or environment-dependent mode selection is permitted.

Preserve `cmd.Dir`, explicit `cmd.Env`, empty stdin, per-stream caps, timeout limits, `Setpgid`, negative-PID SIGKILL cancellation and `WaitDelay`. Do not refactor result or cancellation semantics while adding the flag. A nonzero command exit remains a succeeded execution with nonzero `ExitCode`.

Existing `schemaJSON`, `ToolInfo`, `shell/options.go` comments and `shell/doc.go`: describe a command executed with host-configured shell policy in the workspace. Keep instance-independent metadata, fresh schema copies and exactly the current schema properties. Do not add executable, environment, startup mode or argv fields to `Args` or its model schema. Keep current handling of unknown raw JSON fields; test that a model-provided mode/environment/executable field cannot alter execution even when ignored by leaf JSON decoding. The mounted normalizer may reject those fields.

## Tests and observable acceptance

Extend existing `shell/options_test.go` and `shell/shell_test.go`; new test functions under those files are proposed implementation artifacts.

1. Constructor tables prove omitted options, empty mode and explicit login resolve identically; explicit non-login resolves distinctly; unknown strings, whitespace/case variants and negative cap fail; multiple options still fail. Validate is independently callable on portable builds.
2. A temporary executable argv recorder records argument count and bytes (for example NUL-delimited output with a fixed `/bin/sh` shebang that does not evaluate its arguments). Both modes supply exactly the expected flag and one unchanged command. Include single/double quotes, embedded newlines, dollar expansion text, backticks, semicolons, pipes and redirects. This recorder is a test fixture only, never a production workaround.
3. Run real `/bin/sh` commands with quotes, newlines, pipelines and redirects in a canonical temporary workspace; assert exact decoded stdout/stderr, file content and exit code, not just outcome. Assert empty stdin produces EOF and `$-` lacks `i` in non-login mode. Include a deliberate nonzero exit.
4. Use a temporary HOME with a `.profile` that exports a unique per-test canary and writes a marker at a known absolute temporary path. Pass a deliberately constructed environment containing only the fixture HOME, a safe PATH, and fixture path variables; omit the canary. Run a command that prints cwd, HOME and canary state and verifies a relative workspace file. Non-login output must show the fixture HOME and workspace, canary unset, and no marker on disk or canary in either stream. Explicitly source that same file in a separate control invocation to prove both canary and marker are detectable. Delete the control marker before any repeated negative run. This control does not stand in for argv/default-mode tests.
5. Exercise timeout, output truncation and environment assertions locally in non-login mode and in both modes in the controlled login CI container described below. Add real in-flight parent cancellation: wait for the command's ready marker before canceling; assert canceled category, no timeout misclassification and bounded return. The current `TestRunParentCancellation` only covers an already-canceled context.
6. Strengthen timeout and cancellation process-group evidence: start a non-detached descendant with a ready handshake and a delayed sentinel write; record its PID, cancel/timeout after readiness, and prove it cannot produce the sentinel after its deadline. Bound polling and clean up the exact fixture process group on every failure. Prefer a helper process the test can reap; when using OS liveness probes, distinguish a zombie from a running child rather than requiring immediate `ESRCH`. Do not claim containment of deliberately detached descendants.
7. Cover direct constructor option and Env mutation after `New`; assert the already-constructed tool retains its policy. For explicit empty Env, test a synthetic parent-only canary is absent, rather than assuming the shell exports zero variables (shells can synthesize PWD/SHLVL).

Use curated test environments for new tests and revise existing `hermeticShellEnv` so shell regressions cannot inherit startup hooks such as `BASH_ENV` or `ENV` from the developer. Change the existing `newToolInTempDir` test helper and any direct real-shell tests to select non-login mode by default in the test suite; this does not change production constructor defaults. Keep constructor normalization and the argv recorder responsible for the portable exact login/default contract. Real login execution is permitted only in the dedicated CI container described in package 3, including ordinary timeout, output and environment tests that happen to use login mode. Introduce proposed test-only opt-in `EINO_TOOLS_TEST_LOGIN=1` that adds real login variants to the regression table only in that container; document that developers must not set it on their host. This is test infrastructure, not a product feature flag. Never read or execute the real HOME profile. Give real executions an outer test/context deadline.

Verification: `go test -race ./shell` and root module vet/lint gates from the handoff. Required fixture subtests must actually execute on Linux and macOS CI, not silently skip. Existing result forward-compatibility and schema ABI tests must pass unchanged in meaning.

## Boundaries

The library promises flag selection, single command argument and retained process execution controls. It does not promise that all binaries named by `ShellBinary` avoid startup files with `-c`. For Bash under its own name, `BASH_ENV` can still cause startup commands; for other executables the host must verify semantics. `Env=nil` retains existing leaf inheritance timing; an explicit environment remains a replacement. No environment scrubbing is added to production code.
